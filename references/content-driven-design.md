# 内容驱动设计规范

这份规范用于小红书 1080×1440 卡片系列。原则只有一个：**先理解内容，再决定视觉；先决定阅读结构，再决定装饰。**

不要从风格名开始，也不要因为正文里出现一个关键词就直接套模板。每次写卡前先完成内容诊断，再做风格匹配，并把判断记录在 `analysis.md` 或项目任务说明里。

## 1. 内容诊断

先用一页纸回答下面的问题。回答不完整时，不进入 HTML 实现。

| 问题 | 要回答的内容 |
|---|---|
| 一句话主张 | 用户看完这一组图，应该记住什么？只能有一个主句 |
| 目标读者 | 谁会停下来？他当下要解决什么问题？ |
| 阅读动作 | 停留、理解、比较、照做、收藏、转发，哪个是第一动作？ |
| 内容类型 | 观点、教程、流程、清单、对比、数据、故事、产品/案例，选一个主类型 |
| 证据形态 | 数字、步骤、命令、案例、引语、规则、前后差异，内容靠什么成立？ |
| 信息关系 | 顺序、层级、因果、对比、集合、循环，哪一种关系最重要？ |
| 情绪温度 | 冷静、专业、警示、亲近、手作、戏剧、轻松，选一个主温度 |
| 收藏/转发理由 | 用户为什么要保存或发给别人？ |
| 不可删信息 | 即使需要拆页，也不能牺牲的事实、数字或结论 |

### 内容契约

将诊断压缩成下面的契约，供风格选择和页面拆分使用：

```yaml
content_contract:
  thesis: "一句话主张"
  audience: "主要读者与使用场景"
  primary_action: understand # stop | understand | compare | act | save | share
  content_type: framework # opinion | tutorial | workflow | checklist | comparison | data | story | product | framework
  evidence: [steps, examples]
  information_topology: sequence # hierarchy | sequence | cause-effect | comparison | collection | cycle | narrative
  emotional_temperature: professional
  save_reason: "用户收藏的具体理由"
  must_keep: ["不可删信息"]
  recommended_pages: 6
```

## 2. 风格匹配决策

按下面顺序做判断，不允许由第一条关键词直接决定风格：

1. **先看信息拓扑**：内容是怎么被理解的？流程优先选 flow，左右判断优先选 comparison，层级和指标优先选 grid/list，观点和叙事优先选 editorial/hero。
2. **再看证据形态**：数字、阶段编号、系统框架适合 Swiss；引用、目录、论证适合 Editorial；单一结论、金句和少量原则适合 Zen；多格信息、tips 和结论框适合暖米白原版。
3. **再看受众语气**：专业/克制、警示/强势、亲近/手作、活泼/轻松分别限制装饰、色彩和标题语气。
4. **最后看承载能力**：如果内容需要 6 个以上条目或多个长句，排除 Zen 等低承载风格；如果内容只有一句判断，排除高密度学习笔记式布局。
5. **检查封面与内容页是否都能成立**：封面负责停留，内容页负责扫描；不能因为封面好看就强行让内容页使用同样的密度。

### 推荐输出

每次至少记录三项：

```markdown
首选：Swiss + sequence
理由：信息是阶段编号和闸口构成的框架，网格编号让六阶段一眼可扫描。
备选：Editorial + narrative
理由：若重点从框架改成观点与来源论证，编辑感阅读路径更合适。
排除：Zen
理由：标题冲击力有限，且无法承载每阶段的机制和产物。
```

### 混合主题裁决

同一份内容出现多个信号时，按以下优先级裁决：

`信息拓扑 > 证据形态 > 阅读动作 > 受众语气 > 主题名词`

例如“AI 工具流程”不能只因为有 AI 就选 Notion：

- 阶段编号、指标、系统框架是主体：`Swiss`。
- 论点、引用、目录和反模式是主体：`Editorial`。
- 单一结论、金句、少量原则是主体：`Zen`。

## 3. 封面 brief

封面只做一件事：让用户在缩略图里立刻知道“这是什么、为什么值得继续看”。封面不是总览页，也不是把所有知识点塞进首张图。

```markdown
## Cover Brief
- Kicker：来源/身份/主题标签，1 行
- 主标题候选：2-3 个，中文钩子优先
- 最终主标题：不超过 3 行，强调词 1-2 个
- 副标题：解释范围或结果，最多 2 行
- 主视觉锚点：一个，必须和内容语义有关
- 承接装饰：阶段序列 / 目录 / 数据格 / 证据片段，选一个
- CTA：左滑开拆 → 或与风格一致的短句
- 背书：来源、日期或系列名，非必要不抢主标题
```

### 封面硬规则

- 中文钩子优先；英文风格术语只能辅助，不得取代核心标题。
- 主标题常规为 90–116px、900 字重；只有标题不超过三行且装饰不竞争时，才允许 128–130px。
- 标题区最多一个主装饰锚点：高亮块、色块、胶带、下划线、描边数字或窗口 prompt 只能选一个主角。
- 下半屏必须有**内容型承接**，例如六阶段序列、目录栏、数据格、流程带或证据片段；随机几何图形不算承接。
- 封面元素控制在 6 组以内：kicker、标题、副标题、主锚点、承接装饰、CTA/背书可合并。
- 关键文本和语义装饰距画布边至少 40px；顶部右侧和底部 10% 留给平台 UI 与安全区。
- 缩小到约 25% 检查：先读到主标题，再读到主题范围，最后才看到装饰和背书。

## 4. 内容页分区

内容页采用“**一个主结构 + 一个辅助结构 + 一句结论**”的骨架。每页只解决一个阅读问题，不把整篇文章缩进一张图。

### 主结构选择

| 内容关系 | 主结构 | 推荐表现 |
|---|---|---|
| 顺序/流程 | flow | 节点、箭头、阶段编号 |
| 层级/框架 | grid/list | 分组、编号、层级线 |
| 左右判断 | comparison | 双栏、前后、正反 |
| 因果/闭环 | loop/flow | 回路箭头、触发条件、回写 |
| 集合/清单 | list | 统一行骨架、勾选或标签 |
| 观点/论证 | editorial | 引语、规则线、目录、证据栏 |
| 单个案例 | case study | 现象 → 机制 → 结果 |

### 一条知识点的稳定骨架

推荐每条都尽量保持同样的阅读顺序：

`编号/标记 → 名称 → 一句话机制 → 产物、数字或证据 tag`

如果正文需要行内加粗、代码或链接，HTML 必须写成“图标 + 一个正文块”：

```html
<div class="row">
  <span class="dot" aria-hidden="true"></span>
  <span class="copy">普通文本 <b>重点文本</b> 后续文本</span>
</div>
```

不要让普通文本节点、`<b>`、代码和标签作为 flex 容器的同级子节点，否则浏览器会把它们拆成匿名 flex item，破坏自然换行和阅读顺序。

### 密度和拆页

- 封面：1 个主命题，最多 1 个辅助数字或范围提示。
- 铺垫页：1 个问题 + 2–4 个解释点，给核心页建立语境。
- 核心页：1 个主结构，通常 3–6 个条目；正文 22–25px，行距至少 1.4。
- 高密度页：最多 7 个短条目；每条只保留一个动作或事实，不能同时塞解释、例外和结论。
- 一页出现两个以上长段落、两个以上视觉容器或超过 7 个条目时，优先拆页。
- 结尾页：1 个总结结论 + 1 个行动/互动，不再引入新的事实。
- 用真实流程、示例、对比或数据填补留白，不用 `margin-top: auto` 把死区伪装成呼吸感。

### 内容页装饰规则

- 装饰必须表达阶段、目录、数据、因果、证据或语气中的至少一项。
- 每页只设置一个主视觉锚点，其他装饰降为辅助层级。
- 装饰放在内容区外围或分区边界，不进入正文列，不制造第二条阅读路径。
- 风格越复杂，正文越要收敛；装饰不能与标题或结论使用同等视觉重量。
- 结论框要总结本页已经出现的内容，不能用泛泛的“收藏/点赞”替代结论。

## 5. 发布前验收

### 内容验收

- [ ] 一句话主张在封面和第一张内容页一致
- [ ] 每页只有一个主要阅读问题
- [ ] 每页有清晰的主结构和结论
- [ ] 条目、数字、来源与原文一致
- [ ] 结尾没有引入新事实

### 视觉验收

- [ ] 缩略图先读标题，再读范围，再读 CTA
- [ ] 标题强调词不超过 1–2 个
- [ ] 下半屏没有无意义死区
- [ ] 装饰不遮挡正文，不产生第二阅读路径
- [ ] 页面之间共享背景、字体、边框、强调色和编号语法

### 工程验收

- [ ] 每张 HTML 带 `meta[name="card-size"]` 和固定画布尺寸
- [ ] `check-overflow.py` 通过，内容距边至少 40px
- [ ] 浅底卡按真实设计底色运行像素检查
- [ ] HTML 改动后重新生成对应 PNG，源文件与预览文案一致
- [ ] 检查 `flex` 行内正文是否包在 `.copy`/`.body` 中
- [ ] 最后从缩略图和实际尺寸各看一遍，而不是只看源码

## 6. 示例：同一主题的不同匹配

以“AI-Native SDLC 六阶段”为例：

| 内容重点 | 首选风格 | 页面结构 | 为什么 |
|---|---|---|---|
| 阶段、闸口、指标和系统关系 | Swiss | sequence + grid | 编号和网格让框架一眼可扫描 |
| 观点、来源、目录和反模式 | Editorial | narrative + toc | 适合建立论点和编辑感阅读路径 |
| 六阶段完整机制、每阶段都有长解释 | Zen | 不推荐 | 承载力不足，细节会被压缩成小字 |

这里的主题名词相同，但风格随“用户要怎么读”和“内容靠什么成立”变化。这个差异才是内容驱动选型的核心。
