# 自适应卡片比例设计

## 目标

比例预设和自定义宽高应同时控制预览画布、卡片布局与最终截图。切换尺寸只影响运行时渲染，不修改 `cards/` 下的 HTML 源文件，并保证预览与截图一致。

## 方案

在运行时向卡片 HTML 注入一段高优先级样式，将 `html` 和 `body` 的宽高覆盖为当前目标画布尺寸。卡片原有的 flex、grid、百分比和定位规则继续参与浏览器布局，因此会随目标比例重新排版，而不是继续使用源文件中固定的 `1080×1440` 画布并被裁切。

预览和截图必须复用同一个 HTML 转换函数：

- WebUI 通过带卡片名及目标宽高的预览端点加载转换后的 HTML。
- `shooter.py` 截图时生成临时的转换后 HTML，Chrome 截图完成后清理临时文件。
- 普通 `/cards/` 文件访问、源码读取和保存行为保持不变。

## 交互

- 点击比例预设后更新宽高输入框、激活状态与预览内容，并重新计算适配缩放。
- 点击“应用”后使用自定义宽高刷新预览；若尺寸恰好匹配预设，则同步激活对应预设，否则不激活预设。
- 切换卡片和保存源码后，继续使用当前目标尺寸刷新预览。
- 截图和全部截图继续读取同一份画布状态。

## 边界与错误处理

- 宽高必须是正整数；无效自定义输入不改变当前画布，并在状态栏提示。
- 自适应只覆盖画布尺寸和溢出行为，不重写卡片内容、字号或业务样式。
- 固定像素元素不会被智能重设计，但不再受源文件固定 body 宽高限制；复杂的跨比例视觉编排仍可由卡片自身的媒体查询处理。

## 验证

- 检查 3:4、1:1、9:16、16:9、4:5 的按钮、输入框、激活状态和预览同步。
- 对至少一个固定 `body` 尺寸的卡片生成不同比例截图，验证输出尺寸正确且运行时覆盖生效。
- 验证切换比例和截图不会修改卡片源文件。
- 运行 Python 语法检查并验证服务端预览端点。
